# Data dictionary

Generated by `notebooks/lib/datagen.py` (Phase 2) and written as Bronze
Delta tables by `notebooks/01_generate_synthetic_data.py`. All values are
synthetic; no real customer, account, or card data exists anywhere in this
project. `simulated_annual_value` and `churn_label_90d` are explicitly
simulated placeholders, not real business metrics.

Scale (default): 8,000 customers × up to 12 months of monthly aggregated
activity, ending at a fixed reference month-end (2026-06-30) so generation
is reproducible regardless of when it is run. Some customers signed up
during the 12-month window and have fewer than 12 monthly rows — this is
intentional (new customers), not missing data.

## `customers` (one row per customer)

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | Synthetic identifier, format `CUSTnnnnnn`. Not a real account number. |
| `signup_date` | date | Synthetic account-opening date. |
| `tenure_months` | int | Months between `signup_date` and the reference date. |
| `age_band` | string | One of `18-24`, `25-34`, `35-44`, `45-54`, `55-64`, `65+`. |
| `acquisition_channel` | string | `Branch`, `Online`, `Referral`, or `Partner`. |
| `home_region` | string | Synthetic region label (`North`/`South`/`East`/`West`/`Central`); not a real address. |
| `customer_value_segment` | string | Baseline simulated value tier: `High`, `Medium`, `Low`. Recomputed from behavior in the Gold `customer_360` table (Phase 3); this Bronze value is a generation input, not the final segment shown in the app. |
| `simulated_annual_value` | double | **Simulated** annual revenue/value proxy in USD. Not a real financial figure. |
| `churn_label_90d` | int (0/1) | **Simulated ground-truth** churn outcome, reserved for optional Phase 7 ML validation only. The mandatory rule-based risk score (Phase 4) must not read this column. |

## `account_transactions` (one row per customer per active month)

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | FK to `customers`. |
| `activity_month` | date | Month-end date for this row. |
| `avg_daily_balance` | double | Simulated average daily balance for the month. |
| `eom_balance` | double | Simulated end-of-month balance. |
| `deposit_count` | int | Number of deposit transactions in the month. |
| `withdrawal_count` | int | Number of withdrawal transactions in the month. |
| `transfer_out_amount` | double | Simulated total transferred out in the month. |
| `salary_deposit_flag` | int (0/1) | 1 if a salary deposit was simulated this month. Used to detect stopped salary deposits. |
| `total_transaction_amount` | double | Simulated total transaction value for the month. |

## `card_usage` (one row per customer per active month)

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | FK to `customers`. |
| `activity_month` | date | Month-end date for this row. |
| `card_spend_amount` | double | Simulated monthly card spend. |
| `card_txn_count` | int | Number of card transactions in the month. |
| `declined_txn_count` | int | Number of declined card transactions in the month. |
| `card_active_flag` | int (0/1) | 1 if any card spend occurred in the month. |

## `app_activity` (one row per customer per active month)

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | FK to `customers`. |
| `activity_month` | date | Month-end date for this row. |
| `login_count` | int | Number of app logins in the month. |
| `session_count` | int | Number of app sessions in the month. |
| `avg_session_minutes` | double | Simulated average session duration. |
| `days_since_last_login_eom` | int | Days since last login, as of month end. |

## `contact_history` (sparse, event-level)

| Column | Type | Description |
|---|---|---|
| `contact_id` | string | Synthetic identifier, format `CNTnnnnnnn`. |
| `customer_id` | string | FK to `customers`. |
| `contact_date` | date | Date of the contact. |
| `channel` | string | `Call Center`, `Branch`, `Chat`, or `Email`. |
| `reason` | string | `Complaint`, `Fee Question`, `Service Request`, `Product Inquiry`, or `Technical Issue`. |
| `is_complaint` | int (0/1) | 1 if this contact was a complaint. |
| `is_resolved` | int (0/1) | 1 if the contact was resolved. |
| `satisfaction_score` | int (1-5) | Simulated satisfaction proxy; low for unresolved complaints. |

## `product_holdings` (one row per customer per active month)

| Column | Type | Description |
|---|---|---|
| `customer_id` | string | FK to `customers`. |
| `activity_month` | date | Month-end date for this row. |
| `product_count` | int | Total products held that month (1 + optional products below). |
| `has_checking` | int (0/1) | Always 1 — baseline product for every customer. |
| `has_savings` | int (0/1) | 1 if the customer holds a savings product that month. |
| `has_credit_card` | int (0/1) | 1 if the customer holds a credit card that month. |
| `has_loan` | int (0/1) | 1 if the customer holds a loan product that month. |
| `has_investment` | int (0/1) | 1 if the customer holds an investment product that month. |

A minority of customers have exactly one product added or removed partway
through the 12-month window, driving the "product holding decreased/
increased" signal used in Phase 4.

## `campaign_history` (sparse, event-level)

| Column | Type | Description |
|---|---|---|
| `campaign_id` | string | Synthetic identifier, format `CMPnnnnnnn`. |
| `customer_id` | string | FK to `customers`. |
| `campaign_date` | date | Date the campaign touch occurred. |
| `campaign_type` | string | `Retention Offer`, `Cross-Sell Offer`, `Satisfaction Survey`, or `Product Announcement`. |
| `channel` | string | `Email`, `SMS`, `Push`, or `Call`. |
| `responded_flag` | int (0/1) | 1 if the customer responded to the campaign. |
| `converted_flag` | int (0/1) | 1 if the campaign led to a conversion (only possible when `responded_flag` = 1). |

## Intentional generation archetypes (not a Bronze column)

Six internal archetypes drive the patterns above (see
`docs/data-quality-report.md` for measured rates): `stable_low_risk`,
`declining_balance`, `disengaging`, `service_issues`, `salary_stopped`,
`strong_retention`. The archetype itself is never written to a Bronze
table — only its effects on the behavioral columns above are, so Phase 3/4
logic must derive risk from behavior, not from a hidden label.

## Gold: `customer_360` (Phase 3 — one row per customer)

Built by `sql/gold/customer_360.sql`. "30-day" and "90-day" changes are
month-over-month and 3-months-over-3-months comparisons (source data is
monthly, not daily — see `docs/free-edition-limitations.md`). Customers
with fewer than 4 months of history get `NULL` 90-day comparisons rather
than a misleading number.

| Column | Description |
|---|---|
| `customer_id`, `signup_date`, `tenure_months`, `age_band`, `acquisition_channel`, `home_region` | Passed through from Silver `customers`. |
| `value_segment` | `High`/`Medium`/`Low`, from Silver `customers.customer_value_segment` (a simulated business-assigned tier, not recomputed here). |
| `simulated_annual_value` | **Simulated** annual value/revenue proxy. |
| `churn_label_90d` | **Simulated ground truth**, reserved for optional Phase 7 ML validation only — never used by the Phase 4 rule-based score. |
| `current_balance`, `avg_balance_90d` | Latest month-end balance; average balance over the trailing 3 months. |
| `balance_change_30d_pct`, `balance_change_90d_pct` | % change in `eom_balance` vs. 1 month ago / 3 months ago. `NULL` if insufficient history. |
| `transfer_out_amount_90d` | Sum of transfers out over the trailing 3 months. |
| `salary_deposit_active` | 1 if the latest month had a salary deposit. |
| `salary_deposit_stopped_flag` | 1 if salary deposits were active in an earlier month but not the latest month. |
| `product_count`, `product_count_90d_ago`, `product_count_change_90d` | Current vs. 3-months-ago product count and the difference. |
| `card_spend_90d` | Sum of card spend over the trailing 3 months. |
| `card_spend_change_30d_pct`, `card_spend_change_90d_pct` | % change in monthly card spend vs. 1 / 3 months ago. |
| `declined_txn_count_90d` | Sum of declined card transactions over the trailing 3 months. |
| `days_since_last_login` | As of the latest month. |
| `login_count_90d` | Sum of app logins over the trailing 3 months. |
| `login_change_30d_pct`, `login_change_90d_pct` | % change in monthly logins vs. 1 / 3 months ago. |
| `app_engagement_score` | Percentile rank (0–100) of `login_count_90d` among all customers — a simple, transparent ranking, not a predictive model. |
| `contact_count_90d`, `complaint_count_90d`, `avg_satisfaction_score_90d` | Trailing-90-day service contact volume, complaint count, and average satisfaction proxy. |
| `unresolved_contacts_total` | Unresolved contacts across all history (not just trailing 90 days). |
| `campaign_count_12m`, `campaign_response_rate_12m`, `campaign_conversion_rate_12m` | Trailing 12-month campaign touch count, response rate, and conversion rate. |

See `docs/representative-customers.md` for five real customer stories
(one per risk driver, plus a high-value "safe" contrast) pulled from an
actual run of this table.

## Gold: `retention_action_list` (Phase 4 — one row per customer)

Built by `sql/gold/retention_action_list.sql`. See `docs/risk-scoring.md`
for the full scoring rule, thresholds, and action-mapping table.

| Column | Description |
|---|---|
| `customer_id`, `value_segment`, `simulated_annual_value` | From `customer_360`. |
| `risk_score` | 0–129, sum of triggered signal points. Transparent point score, not a predictive model. |
| `risk_score_normalized_100` | Display-only `ROUND(risk_score / 129 * 100)` — the 129-point scale above remains the source of truth. |
| `triggered_signal_count` | 0–8, how many of the 8 signals fired ("N / 8"). |
| `risk_segment` | `High` (>=40), `Medium` (15-39), `Low` (<15). |
| `primary_driver`, `secondary_driver` | Highest- and second-highest-point triggered signals, or `'No material risk driver'`/`'None'`. |
| `balance_decline_flag`, `salary_stopped_flag`, `card_spend_decline_flag`, `app_usage_decline_flag`, `complaint_increase_flag`, `long_inactivity_flag`, `unresolved_contact_flag`, `product_decline_flag` | The 8 underlying 0/1 signal flags, for drill-down transparency. |
| `recommended_action`, `recommended_channel` | Assigned only for Medium/High risk; `'No immediate action'`/`'None'` otherwise. |
| `human_review_required` | 1 for Medium/High risk (an action is recommended); 0 otherwise. No action here is automated — a person reviews and executes. |
| `estimated_value_at_risk` | **Simulated** proxy: `simulated_annual_value × (risk_score / 129)`. Not an actuarial estimate. |
| `is_prioritized_audience` | The single canonical "Prioritized Audience" flag: (High risk AND High/Medium value) OR (Medium risk AND High value), with an action assigned and human review required. Used identically by Executive Overview's KPI, Retention Actions' default list + CSV export, and Top Risk Drivers' population — see `docs/risk-scoring.md`. |
| `action_priority_score` | Additive, normalized weighted sum of risk, value, value-at-risk, and actionability (0.40/0.30/0.20/0.10) — see `docs/risk-scoring.md` "Priority ranking formula" for the full comparison against a multiplicative alternative and the adoption rationale. Never shown directly in the UI. |
| `action_priority_rank` | `ROW_NUMBER()` over `action_priority_score` descending (unique, sequential, never tied) — sort key for the Retention Actions page. |
| `priority_tier` | `NTILE(3)` over the same ordering, labeled `A` (top third, most urgent) to `C` (bottom third). |

## Gold: `executive_kpis` (Phase 4 — one summary row)

Built by `sql/gold/executive_kpis.sql`, aggregating `retention_action_list`.
Risk-distribution and value-vs-risk-matrix breakdowns (charts, not scalar
KPIs) are Phase 5 SQL assets built directly on `retention_action_list`.

| Column | Description |
|---|---|
| `total_customers` | All customers. |
| `high_risk_customers`, `medium_risk_customers`, `low_risk_customers` | Reconcile to `total_customers`. |
| `high_risk_high_value_customers` | High risk **and** High value. |
| `prioritized_audience_count` | `SUM(is_prioritized_audience)` from `retention_action_list` — (High risk AND High/Medium value) OR (Medium risk AND High value), with an action assigned. The same figure Retention Actions' default list, its CSV export, and Top Risk Drivers reconcile to exactly. |
| `broad_campaign_audience_count` | Equals `total_customers` — today's blanket-campaign baseline, for contrast with `prioritized_audience_count`. |
| `estimated_value_at_risk_total_simulated`, `estimated_value_at_risk_high_risk_simulated` | **Simulated** sums of `estimated_value_at_risk`, labeled as such. |

## Gold: `churn_model_scores` (optional, Phase 7 — not built by default)

Written only if `notebooks/07_optional_ml_baseline.py` is run. Never read
by the mandatory app.

| Column | Description |
|---|---|
| `customer_id` | FK to `customer_360`. |
| `ml_churn_probability` | Predicted probability from the optional logistic-regression baseline (`notebooks/lib/ml_baseline.py`), fit on all Customer 360 behavioral features. |
| `model_name` | Fixed string identifying the model version, e.g. `behavioral_features_logreg_v1`. |

See `docs/ml-comparison.md` for how this compares to the mandatory
rule-based score — measured on a held-out test set, not this table.
