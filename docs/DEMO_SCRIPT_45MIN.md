## タイムライン

### 0:00–0:05｜課題の再確認とゴール設定（5分）
- CloudNestの7つの課題を復唱し、「今日のデモで何を確認できれば意思決定できるか」を握る。
  1. データが分散し顧客状態を一元把握できない
  2. 優先対応の共通指標がない
  3. 解約判断が経験依存
  4. サポートチケットのテキストが未活用
  5. 経営層が週次でARR at risk等を見たい
  6. 解約予測モデルの学習データがない
  7. アクセス制御・監査・リネージが必要
- 「今日は3,000社の代表サンプル350社の疑似データで、この7つに対する“動くプロトタイプ”をお見せします」と宣言。

### 0:05–0:12｜アーキテクチャ説明（7分）
- `docs/ARCHITECTURE.md` の図を画面共有。Medallion（Bronze/Silver/Gold）を1枚で説明。
- 強調ポイント：「BI・CS運用・ML学習が同じGoldテーブルを見る」＝指標のズレがなくなる。

### 0:12–0:30｜ライブデモ：データ基盤からCustomer 360・ヘルススコアまで（18分）
1. `01_generate_sample_data.py` を実行 → 5ソースの疑似データが生成される様子（課題1）
2. `02_bronze_ingestion.py` → `03_silver_transformation.py` を流し、品質サマリー（除外件数）を見せる → 「クレンジングを自動化している」
3. `04_gold_customer_360.py` → Customer 360 テーブルを `SELECT *` で表示 → 「バラバラだった5システムが1行に」（課題1）
4. `05_health_score_churn_risk.py` → ヘルススコア・リスクティア・`top_risk_reason` を表示 → 「なぜこの顧客が危ないかを言葉で説明できる」（課題2・3）
5. `07_dashboard_queries.sql` の A-1（週次ARR at riskトレンド）・A-4（更新カレンダー×リスク）をSQLエディタで実行 → 折れ線グラフを見せる（課題5）
6. B-1（CSM別優先対応リスト）を実行 → 「CSMは今日誰に電話すべきかが一目で分かる」（課題2）

### 0:30–0:38｜サポートチケットNLP分析（8分）
- `06_support_ticket_nlp_analysis.py` を実行し、感情・トピック分類結果を表示（課題4）。
- リスクティア別のネガティブチケット比率を見せ、「言葉が解約の先行指標になっている」ことを示す。
- **重要**：`ai_analyze_sentiment` / `ai_classify` のSQLサンプル（06内のコメント）を見せ、「これは1行のSQLでLLM品質に置き換えられる。今日はキーワードベースですが、本番ではDatabricksネイティブのAI Functionsを使います」と説明。

### 0:43–0:45｜まとめ（2分）
