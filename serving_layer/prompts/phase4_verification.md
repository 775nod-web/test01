# Phase 4: 検証プロンプト

Phase 1〜3 の成果物に対して、以下を確認・記録してください。

## API 契約の整合性チェック

- `backend/models.py` の各フィールドが、Gold layer のテーブル定義（本タスクのテーブル定義メモ）と1対1で対応しているか突き合わせる。
- フロントエンドの型定義（`frontend/src/api/client.ts` 周辺）がバックエンドのレスポンス型とズレていないか確認する。

## ビジネス目的の充足チェック

CLAUDE.md の「ビジネス目的」表を見ながら、各画面が実際にその意思決定を助ける情報を出しているか自己レビューする:

- 経営KPIダッシュボード: 経営層が「今日のビジネスの調子」を30秒で把握できるか？
- プラン別売上: 「どのプランが収益停滞しているか」が数値とビジュアルの両方で分かるか？
- 要フォローアップ顧客: CS/営業が「今日誰に連絡すべきか」の優先順位をつけられるか？
- データ品質サマリー: データエンジニアが「どのテーブル・どのチェックで問題が起きているか」を一覧できるか？

## 動作確認

- `npm run build`（frontend）と Python の構文チェック（`python -m py_compile` 等）を実行し、エラーがないことを確認する。
- ローカルで API をモックデータで起動し、4画面をブラウザで開いて崩れがないかスクリーンショットを取る（可能な環境であれば `/run` や `/verify` スキルを使う）。
- 本番の Databricks ワークスペースに接続できる環境であれば、`gold` スキーマに対して実際にクエリが通ることを確認する。

## 仕上げ

- `serving_layer/README.md` を最終化し、セットアップ手順・アーキテクチャ図・各画面のスクリーンショット（あれば）・既知の制約を記載する。
- 未実装/意図的にスコープ外とした項目（書き込み機能、認証のパーソナライズ等）を README に明記し、後続タスクとして残す。
